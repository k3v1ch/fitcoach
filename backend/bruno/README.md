# Bruno: тесты API спортивной организации

Коллекции подготовлены по Java-контроллерам и DTO текущего backend и сверены с `sports-organization-api.md` от 2 октября 2026 года. Документ использован как спецификация API. Автоматическая регрессия проверяет текущую реализацию; проверки расхождений с ТЗ находятся отдельно.

| Коллекция | Запросов | Назначение |
| --- | ---: | --- |
| `automatic-public` | 15 | CSRF, отсутствие сессии, валидация регистрации и сброса пароля. Аккаунт не нужен |
| `automatic-e2e` | 118 | Последовательный сценарий с активным тестовым аккаунтом; данные создаются автоматически |
| `manual` | 84 | Запросы для ручного запуска; есть примеры для всех 72 mappings текущих контроллеров |
| `manual-spec` | 19 | Проверки по ТЗ, включая отсутствующие методы и известные расхождения |

Каждый запрос содержит проверку HTTP-статуса во вкладке Tests. В автоматических сценариях дополнительно проверяются содержимое ответов, пагинация, сохранение изменений, остаток задолженности, идемпотентность платежей, блокировка изменений закрытой тренировки, скачивание и изоляция записей организаций. Cookie хранится Bruno; CSRF и полученные ID сохраняются через `bru.setVar()` в памяти.

## Перед запуском

1. Запустите backend и PostgreSQL по его README, например `docker compose up --build` из папки backend. По умолчанию API находится на `http://localhost:8080`.
2. При локальном HTTP нужна настройка `SESSION_COOKIE_SECURE=false`, иначе cookie сессии не будет отправляться.
3. Для `automatic-e2e` нужен подтверждённый ACTIVE аккаунт с известным паролем. Для создания такого аккаунта используйте запросы регистрации из `manual`; токен подтверждения получите из письма. Пароль — 15–128 символов. В текущей реализации создание организации добавляет создателю TRAINER-членство с правами; отдельная предварительно настроенная организация для сценария не нужна.
4. E2E создаёт две новые организации на каждый прогон. Большинство сущностей нельзя удалить через текущий API, поэтому данные остаются. Используйте отдельную тестовую БД. Нельзя запускать сценарий параллельно или начинать с середины без уже созданных ID.

## Ручной запуск в Bruno Desktop

1. Выберите **Open Collection** и откройте одну из четырёх папок, в которой лежит `bruno.json`.
2. Выберите окружение `Local`. Для аккаунтов создайте копию `environments/Local.bru` с именем `Private.bru`, заполните `baseUrl`, `email`, `password` и выберите `Private`. Этот файл исключён из Git. Не записывайте реальные пароли в поставляемый `Local.bru`.
3. Выполните **Получить CSRF → Вход → Новый CSRF после входа**. После выхода, смены аккаунта или пароля снова получите CSRF. Cookies должны быть включены. Для `automatic-public` очистите cookie хоста, если ранее вошли в аккаунт в Desktop.
4. В `manual` запускайте отдельные запросы в нужном порядке. ID из POST автоматически сохраняются в памяти этой коллекции; при перезапуске приложения укажите ID существующих объектов в окружении. Для вручную создаваемых данных задайте уникальный `runId` и `paymentKey`. Одинаковый `paymentKey` намеренно повторяет прежний платёж, поэтому для нового платежа меняйте ключ.
5. Ручную коллекцию целиком через Runner не запускайте: она содержит сброс и смену пароля, удаление, изменение состояния и запросы для разных ролей. Ожидаемый статус в Tests относится к предусловиям конкретного запроса.

Даты ручного окружения — примеры. Обновите `today`, `joinedOn`, периоды и сроки под свой сценарий. В автоматическом E2E они вычисляются заново; `today` берётся на день раньше запуска, чтобы не попасть в будущую дату оплаты из-за часового пояса сервера. Для загрузки используются небольшие PNG и TXT из `fixtures/`; файл можно заменить во вкладке Body.

## Автоматический запуск через CLI

Из папки `backend/bruno`:

```powershell
npm install
npm run validate
.\run.ps1 -Suite public
```

Перед полным сценарием подготовьте окружение:

```powershell
Copy-Item .\automatic-e2e\environments\Local.bru .\automatic-e2e\environments\Private.bru
# Заполните email и password в Private.bru, при необходимости baseUrl.
.\run.ps1 -Suite e2e -Environment Private
```

Скрипт запуска останавливается при первом падении и возвращает exit code Bruno. Отчёты HTML и JUnit создаются в `automatic-public/reports/` или `automatic-e2e/reports/`; тела запросов, ответов и заголовки исключены из отчётов. Команды Runner и флаги соответствуют [официальной документации Bruno CLI](https://docs.usebruno.com/bru-cli/commandOptions).

Если CLI установлен глобально, можно запустить напрямую:

```powershell
Set-Location .\automatic-public
bru run requests --env Local --bail
```

Для E2E аналогично: откройте `automatic-e2e` и используйте `--env Private`. В CI передавайте секреты через защищённые переменные CI и временное окружение или `--env-var`; не добавляйте их в Git и вывод консоли. Условия CI: уже запущенный API, PostgreSQL и ACTIVE тестовый пользователь. Для CI используйте JUnit-отчёт из `run.ps1`.

## Что ещё проверять вручную

Пошаговые сценарии и матрица прав: [MANUAL-CHECKLIST.md](MANUAL-CHECKLIST.md). Различия ТЗ и кода: [SPEC-GAPS.md](SPEC-GAPS.md).

`manual-spec` содержит ожидаемые результаты из ТЗ и может падать на текущем backend. Отсутствующий controller mapping после авторизации может вернуть 404/405 или стандартную ошибку Spring. Это не успешное выполнение ожидаемого API-метода.

## Проверка самой коллекции

`validate.cjs` использует официальный `@usebruno/lang`: разбирает все `.bru`, JSON-тела и окружения, компилирует JavaScript и проверяет файлы multipart. Чтобы также сверить покрытие с контроллерами:

```powershell
node .\validate.cjs ..
```

Результат — `validation.json`. При подготовке проверены 236 запросов, 411 блоков скриптов; ручные примеры покрывают 72 из 72 mappings. Использован Bruno CLI 4.2.0 и парсер 0.40.0.

**Полный прогон по реальному backend пока не выполнен:** на момент подготовки `localhost:8080` не принимал соединения, credentials тестового аккаунта не предоставлены. Проверка формата и покрытия не подтверждает корректность поведения сервера.
