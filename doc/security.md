# ИС «ФитКоуч» — меры защиты (инфраструктура)

Что закрыто на уровне сервера и окружения прод-стенда `https://fitcoach.keldari.online`,
какие требования ТЗ (раздел 3.4) остаются за бэкендом, и какие риски приняты.

## 1. Соответствие требованиям ТЗ

| № | Требование | Инфраструктура | Бэкенд |
|---|---|---|---|
| Б1 | Аутентификация | закрытые сервисы (БД, бэкенд) не видны снаружи | сессии Spring Security, вход по паролю |
| Б2 | Пароли и токены | секреты в `.env` (600), не в git; пароль БД сгенерирован заново | Argon2id; токены ссылок — хеш, 30 минут, одноразовые |
| Б3 | RBAC | — | права проверяются на сервере для каждого запроса |
| Б4 | Изоляция данных | БД в отдельной сети без выхода в интернет | `organizationId` и связанные id проверяются, чужое → 404 |
| Б5 | Защита API | nginx: `limit_req` 20 запросов/с на IP для `/api`, 10 в минуту для входа, регистрации и сброса пароля; `limit_conn` 50 | валидация, лимиты на регистрацию и восстановление, параметризованные запросы |
| Б6 | Защита передачи | только HTTPS (Let's Encrypt, TLS 1.2/1.3), HTTP → 301, HSTS год; cookie `Secure` | `SESSION_COOKIE_SECURE=true`, `HttpOnly`, `SameSite=Lax` |
| Б7 | Персональные данные (152-ФЗ) | данные хранятся только на этом сервере, БД наружу закрыта, бэкапы с правами 700 | согласия и минимизация данных |
| Б8 | Журналирование | логи nginx и бэкенда в Docker с ротацией; журнал выкладок; логи CI | журнал действий (activity) |
| Б9 | Файлы | nginx пропускает тело до 12 МБ; загрузки в отдельном томе, не в публичном каталоге | лимит 10 МБ, проверка типа и сигнатуры, доступ по правам |
| Б10 | Секреты | `/opt/fitcoach/shared/.env` (root, 600), `.env` в `.gitignore`, пароль в логи и аргументы процессов не попадает | секреты из переменных окружения |

## 2. Сеть

- **ufw**: входящие разрешены только на 22/tcp (SSH), 80/tcp и 443/tcp; остальное — запрет по умолчанию.
- **DOCKER-USER** (`fitcoach-docker-fw`, systemd): Docker публикует порты в обход ufw, поэтому отдельный
  фильтр пропускает в контейнеры извне только 80/443. Даже если кто-то запустит `backend/docker-compose.yml`
  с портами 5432/8080, снаружи они будут закрыты.
- **TrafficGuard** (antiscan): известные сети сканеров блокируются на входе сервера и на пути к контейнерам.
- Наружу публикуется только `edge`; `backend` и `db` доступны только внутри сетей Docker,
  сеть `data` (БД) — `internal`, без выхода в интернет.

## 3. SSH и доступ

- root и все прочие пользователи входят **только по ключу** (`/etc/ssh/sshd_config.d/00-key-only.conf`),
  root — `prohibit-password`.
- Пользователь `git` — по паролю команды или по ключу (`Match User git` в `00-fitcoach-hardening.conf`).
  Ключ надёжнее: публичный ключ добавляется в `/home/git/.ssh/authorized_keys`.
- `00-fitcoach-hardening.conf`: `AllowUsers root git`, `X11Forwarding no`, `LoginGraceTime 30`;
  пользователю `git` запрещены TTY, проброс портов, агента и туннели.
- Пользователь `git` — оболочка `git-shell`: доступны только `git push/pull` и команда `ci-status`.
- **fail2ban** (sshd): 3 неудачные попытки за 10 минут → бан на 24 часа, повторно дольше (до 48 часов).
  Снять бан: `fail2ban-client set sshd unbanip <IP>`.
- Защита `master` (хук `update`): нельзя удалить ветку и переписать историю.

## 4. Контейнеры

| Сервис | Пользователь | Ограничения |
|---|---|---|
| backend | uid 10001 (не root) | `cap_drop: ALL`, `no-new-privileges`, лимит памяти 768 МБ |
| db | postgres | `no-new-privileges`, лимит 384 МБ, без портов и интернета |
| edge | nginx (воркеры) | `no-new-privileges`, лимит 128 МБ, `server_tokens off` |

Образы собираются из репозитория и называются `fitcoach.local/*` — из публичного реестра
с таким именем ничего не скачается.

## 5. HTTP-заголовки (edge)

`Strict-Transport-Security: max-age=31536000`, `Content-Security-Policy` (скрипты только со своего домена,
стили и шрифты — свой домен и Google Fonts, `frame-ancestors 'none'`, `object-src 'none'`),
`X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Permissions-Policy` (камера, микрофон, геолокация, оплата — запрещены), `Cross-Origin-Opener-Policy: same-origin`.

## 6. Резервное копирование и обновления

- Ежедневный бэкап БД, файлов и репозитория (03:30 UTC) и бэкап перед каждой выкладкой; хранение 14 дней.
- Автоматические обновления безопасности (`unattended-upgrades`); сертификат продлевается сам.
- Выкладка только через CI: тесты → сборка → проверка здоровья → автоматический откат при сбое.

## 7. Принятые риски и рекомендации

| Риск | Состояние |
|---|---|
| Слабый пароль `git` + CI/CD: подобравший пароль может выкатить свой код на прод | принят командой; смягчение — fail2ban (3 попытки → бан 24 ч), `git-shell` без туннелей, защита `master`, бэкапы перед выкладкой |
| Бэкапы на том же диске | при потере сервера пропадут вместе с ним — нужна копия вне сервера |
| Откат выкладки не откатывает миграции БД | при неудаче — восстановление из `pre-deploy` бэкапа (`doc/deploy.md`, раздел 7) |
| 30–60 с простоя API при выкладке изменений `backend/` (сайт при этом открывается) | приемлемо для демо; для прода — второй экземпляр бэкенда |
| `GET /api/v1/me` без входа создаёт серверную сессию | замечание бэкенду; nginx ограничивает частоту запросов |
| Документация API (`backend/sports-organization-api.md`) расходится с кодом: `POST /auth/register` не принимает `fullName` | замечание бэкенду; фронтенд отправляет только `email` и `accountType` |
| Swagger UI открыт публично | нужен тестировщику по ТЗ; на прод-стенде можно закрыть |
